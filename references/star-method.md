# STAR Method for CV Bullets

STAR = **S**ituation, **T**ask, **A**ction, **R**esult.

On a CV bullet you don't have room for all four explicitly, you compress them into one sharp sentence. The point is to make the bullet answer:
- What was the context?
- What did *you* specifically do?
- What was the outcome?

**The non-negotiable shift is responsibility → outcome, not "add a number".** The point is to move a bullet from what the role *covered* to what *changed* or what you *achieved*. A number sharpens the outcome and is the ideal, but a qualitative outcome (what it enabled, what shipped, what you learned, what got better) already beats a responsibility. Don't withhold the fix or make the candidate feel the bullet is broken just because there's no metric.

## The compressed STAR formula

Most strong CV bullets fit this pattern:

> **[Action verb]** [what you did], [how / using what], **resulting in** [the outcome or impact; a number if you have one].

Examples:
- "Built a payment retry system using AWS Lambda and SQS, reducing failed transactions by 23% (€180k/year recovered)."
- "Led migration of 14 microservices from EC2 to Kubernetes, cutting infrastructure cost by 35% and deploy time from 30 min to 4 min."
- "Designed and shipped React component library used by 4 product teams, eliminating ~600 lines of duplicate code per app."

## Diagnosing weak bullets

| Weak bullet | What's missing | Fix |
|---|---|---|
| "Worked on backend services" | Action, scope, outcome | "Built and maintained 6 Node.js microservices handling 2M+ daily requests" |
| "Helped improve performance" | Who did what, how much | "Cut API p95 latency from 800ms to 120ms by introducing Redis caching" |
| "Responsible for code reviews" | Passive, no outcome | "Reviewed 200+ PRs/year, mentoring 3 junior engineers who shipped to production within 6 weeks" |
| "Used React and TypeScript" | Tech list, not accomplishment | "Shipped a React/TypeScript dashboard adopted by 80% of internal analytics users in Q2" |

## When the user doesn't have numbers

This is the most common situation. The CV bullets are vague because the underlying numbers were never written down.

**Don't make numbers up.** Ask the user:

- "How many users / customers did this affect?"
- "Roughly how much time did it save (per day, per week)?"
- "How many people were on the team? What was your specific part?"
- "What was the business outcome, revenue, retention, error rate?"
- "Before vs after, anything you can compare?"

Even rough estimates are better than no number. "Reduced support tickets" → "Reduced support tickets by ~30%". A range is fine. A "before/after" comparison is fine. "First in the company to do X" is fine. A null result is fine if the *learning* is meaningful ("ran an A/B test on checkout flow; null result confirmed existing design").

## Non-tech contexts (translating soft impact)

For career-changers, results don't have to be code metrics. Examples that translate:

- Logistics coordinator: "Negotiated freight contracts covering €2.4M annual shipping volume across 6 carriers, cutting cost per pallet by 12%."
- Teacher: "Redesigned 8th-grade math curriculum; class average rose from 67% to 82% over two years."
- Customer support: "Resolved 40+ tickets/day; reduced average response time from 24h to 4h by introducing tag-based routing."

The same framing works in any field: scope, action, outcome.

## Action verbs to lean on

Strong action verbs (use these):
- **Built / Shipped / Launched / Delivered**, for things you made
- **Led / Drove / Owned / Spearheaded**, for things you took responsibility for
- **Reduced / Increased / Improved / Cut**, for measurable change
- **Designed / Architected / Engineered**, for technical work
- **Mentored / Coached / Trained**, for people work
- **Analyzed / Investigated / Diagnosed**, for problem-solving
- **Migrated / Refactored / Modernized**, for legacy work

Weak verbs to replace (red flags):
- "Worked on" → what specifically did you do?
- "Helped with" → were you the lead, the contributor, the supporter?
- "Was involved in" → too vague, almost meaningless
- "Was responsible for" → passive; replace with active
- "Assisted in" → if that's literally the role, fine, but usually you did more
- "Participated in" → same issue
